# Architecture

SatyrAV is a single-process, dual-display application built with C++17, SDL3, and FFmpeg. It follows a screen-based architecture where a central `App` class owns the main loop and routes between screen objects.

## Module overview

### App (`src/App.hpp/cpp`)

The application entry point. Owns the `Renderer`, `TextRenderer`, `InputHandler`, and all `Screen` instances. The main loop in `App::Run()` polls SDL events, dispatches input actions, calls the active screen's `Update` and `Draw`, renders popups on top, and presents the master window. The slave window is presented by `PerformanceScreen` directly since it only exists during project playback.

### Screens (`src/screens/`)

Each screen implements the `Screen` interface: `OnEnter`, `OnExit`, `HandleInput`, `Update`, `Draw`. The active screen is set by `App::SwitchScreen(ScreenID)`. Available screens:

- **SplashScreen** — two-phase startup animation (SaTyR logo, then SatyrAV logo with credits). Auto-advances after 3+3 seconds or on any key press.
- **MainMenuScreen** — three options: New project, Load project, Options. Shows the SaTyR logo.
- **NewProjectScreen** — form for revy type, year, creator name. Creates the project directory structure with `schema.toml` and an example scene. *(1.6.2)* Creator is persisted into `[RevyData].Creator` so the Load Project screen can show authorship.
- **LoadProjectScreen** *(rewritten 1.6.2)* — scans `projectsDir` for any sub-folder containing `schema.toml` and parses its metadata once per `OnEnter`. Renders a grouped two-column table (full Revy name / persisted creator) with a live search field, a Revy filter dropdown (auto-populated from the live scan; collapses Jubi + non-Jubi into a shared group), and a sort dropdown (Year / Recent / Name). `TAB` cycles focus across the four input regions; the project list itself skips group-header rows on Up/Down so the cursor always lands on a project.
- **OptionsScreen** — font colour, font size, projects directory, secondary display index, slave window mode, capture mirror display, and *(1.6.3)* audio output device. Saves to platform config path.
- **PerformanceScreen** — the main workspace. Three-column navigator (akts → scenes → commands), cue execution, slave display management. *(1.6.3)* Dispatches `InputAction::FunctionKey` for project audio hotkeys and tracks the currently-playing hotkey so a second press toggles it off. *(2.0.1)* `O` (`InputAction::MarkLine`) appends the last executed cue to the project's fix-it log through `MarkLog`; the cue is captured as a `MarkedLine` when it runs, and a short confirmation is drawn above the master's status line. `SetProject` creates the `fix-it` folder. The options cascade also pushes `GetEffectiveTextColour()` to the slave.

### Core (`src/core/`)

- **CueEngine** — holds the loaded `ProjectData`, manages selection state (current akt, scene, command index), and fires a callback when a command is executed. Provides the options cascade (`GetEffectiveFontSize`, `GetEffectiveBackgroundColour`, `GetEffectiveCapitalize`, `GetTextOutline`, `GetEffectiveParticleTuning`). *(1.6.1)* Adds `GetEffectiveFontPath(bold, italic)` for the four font-style face paths and `GetSubtitle{Italic,Colour,Transparency,PosY}` for `textD` defaults. *(1.6.3)* `GetFunctionKeyAudio(num)` returns the bound F-key audio filename. Particle tunings cascade scene → project → built-in defaults per field; font slots cascade scene → project → Config (and Config falls back to bundled DejaVu). *(2.0.0)* `GetEffectiveAudioFade()` cascades the opt-in audio-fade option the same way as `Capitalize`. *(2.0.1)* `GetEffectiveTextColour()` cascades scene → project → white, and `GetEffectiveBackgroundColour()` now cascades scene → project → black the same way; before, a selected scene always won, so a scene without a background colour was black whatever the project said. Alpha 0 means "not set" at both levels.
- **SchemaParser** — reads `schema.toml` using toml++ and produces a `RevySchema` struct with project-level options and the akt/scene structure. *(1.6.1)* Reads `Options.FontItalic`/`FontBold`/`FontBoldItalic` plus the four `Subtitle*` keys. *(1.6.2)* Reads `RevyData.Creator` and extracts a trailing 4-digit year for sort. *(1.6.3)* Reads the `[Hotkeys]` table. *(2.0.1)* `[Options]` keys are looked up through `OptionKeys`, so any case and the scene spellings work; when a file has both an alias and the documented name, the documented name wins. Colours go through the shared `ParseColour`, except that `SubtitleColour = "grey"` keeps its lighter `#AAAAAA`. Reads `TextColour`.
- **SceneParser** — reads `.ngk` scene files. Handles section parsing (`[Options]`, `[Preload]`, `[Macro]`, `[Commands]`), block constructs (`run{}`, `loop(){}`, `group NAME{}`), compound commands (`&`), macro definition + inline expansion (`macro <Name>`), the `+` concatenation operator inside every text command, and the full modifier chain. *(1.6.1)* Parses the `textbf` / `textit` / `textbfCont` / `textitCont` / `textD` keywords and the inline `bold(...)` / `it(...)` segment wrappers. *(1.6.3)* When a leading bareword doesn't match any known keyword the parser still falls through to `Text` for runtime safety, but stamps `Command::unknownKeyword` and lifts those into a per-scene `Scene::warnings` list (recursing through compound + loop bodies) so Overview Debug can surface typos. Group blocks tag every body command with the group name so the slave can later clear that group selectively. *(1.7)* A `DelimAt` helper recognises three interchangeable string-delimiter pairs — `"..."`, `'...'`, `´...´` (the last being UTF-8 `0xC2 0xB4`) — and all quote-aware scanners (`FindCommentStart`, `SplitArgs`, `SplitPlus`, `StripQuotes`, the bareword check) require the closer to match the opener. Also parses the paren-style `countdown(SECONDS[, "LANG"])` and the bareword `clearCountdown`. *(1.8.2)* The ad-hoc scans for the `#` comment marker and the `&` compound separator were merged into one `FindStructural(line, target)` helper that skips both quoted strings and modifier argument lists — fixing `color(#RRGGBB, …)` and `text "Tom & Jerry"`, which had each been broken by their own hand-rolled splitter. Also parses `typewrite(MS_PER_CHAR, TEXT)` and routes every produced text run through `ExpandLatexSymbols`. *(1.8.3)* Parses `pathMove(P1, …, PN, MS[, MODE], content)` and `layer(N, content)`. *(1.8.4)* Parses the `[Cue]` section in a pre-pass — so `\Name` references resolve whichever side of `[Commands]` it sits on — strips a trailing `\Name` from a command line before the `&` split so the note binds to the navigator row, and warns on notes that are unreferenced, duplicated, or textless. *(2.0.1)* `[Options]` keys go through `OptionKeys` (case-insensitive, one name shared with `schema.toml`, old spellings kept as aliases) and every colour through `ParseColour`; the private named-colour table is gone. `FindOptionCommentStart` keeps a hex value straight after an option's `=` from being read as a comment, and a quoted option value is unquoted. `colour(` is the documented modifier, `color(` still parses. `Scene::sourceLines` keeps the file's lines for the mark-line log.

- **LatexSymbols** *(1.8.2)* — `ExpandLatexSymbols(text)` turns LaTeX-style macros into UTF-8: all Greek plus the `\var` forms, ~45 mathematical symbols, and `\mathbb{X}` for any capital. A macro name is the greedy run of ASCII letters after the backslash, which makes prefixes unambiguous (`\in` / `\infty` / `\int`). Unrecognised macros are copied byte-for-byte — that is what keeps the renderer's `\n` line-break marker working, and it means a typo shows on screen rather than vanishing. Called from `ParseTextRuns`, so every text-bearing command inherits it through one site.
- **OptionKeys** *(2.0.1)* — one table of `[Options]` names shared by both parsers. `LookupOptionKey(name)` maps a name in any case — documented or a pre-2.0.1 alias such as `bc`, `cap` or `backgroundcolor` — to an `OptionKey`; `DocumentedOptionName` / `IsDocumentedOptionName` give the one spelling the docs use, and `ParseOptionBool` reads `true` / `1`. Particle tunables (`RAIN.SPEED`, …) are not in the table and stay with `SceneParser`.
- **MarkLog** *(2.0.1)* — the `O` mark-line log. `MarkFor(scene, cmd)` builds a `MarkedLine` (file name, line number, the line's text from `Scene::sourceLines`); `Append` writes one `HH:MM:SS  File.ngk  line N:  code` line to `<project>/fix-it/ErrorInFiles-YYYY-MM-DD.LOG`, creating the folder if needed and the file on the day's first mark. SDL-free, so it is covered by the core tests.
- **Project** — directory creation, `schema.toml` generation, example scene generation. *(1.6.2)* Persists `Creator`. *(1.6.3)* Emits a commented `[Hotkeys]` example block in new schemas so users discover the feature. *(1.8.0)* The generated `schema.toml` now lists **every** project option, uncommented and at its default, so an operator edits in place instead of consulting the docs; the ten `[Particle.<TYPE>]` tables ship as one documented commented template, since their default is "no override at all". `GenerateExampleScenes` replaces the single example with four tutorial scenes across two akter — one per engine layer — all referencing only the one asset the generator copies in, so a new project runs end to end before any media is added. *(1.8.4)* `FontSize` is generated as `60` rather than the parser's built-in fallback of 25, which is far too small on a projected slave; the fallback itself is deliberately unchanged so existing projects that omit the key don't resize. *(2.0.1)* New projects get a `fix-it/` folder and `TextColour = "white"` in `schema.toml`. The generated scenes no longer set `BackgroundColour`; they mention it in a comment and follow the project's black.
- **Config** — singleton holding global settings (font size, paths, display index, audio device, font-variant paths, fonts dir). Loads/saves from the platform config path. *(1.6.1)* `ResolveFontPath(name)` accepts either an absolute path or a bare filename (resolved against `fontsDir`). *(1.6.3)* `audioDeviceName` selects the SDL output device. *(2.0.0)* `videoZeroCopy` (`[video] zero_copy`, default on) is the switch for the zero-copy video path.
- **Logger** *(1.6.3)* — process-wide singleton that mirrors every message to both stderr (always) and a per-day rotating file at `<SatyrAV>/log/satyrav-YYYY-MM-DD.log`. Mutex-guarded so the decode-thread sites in `MediaPlayer` can log safely. printf-style `Debugf`/`Infof`/`Warnf`/`Errorf` API; per-process file-level filter (default `Info`). *(2.0.0)* Every diagnostic in the render and media code goes through it. On Windows the application is a GUI-subsystem program with no console, so the log file is the only place a failure is recorded.
- **Platform** — platform-specific default paths. Linux: `~/.config/satyrav/config.toml`, `~/satyrav/projects/`, `~/satyrav/FONTS/`, `~/satyrav/log/`. Windows: `Documents\SatyrAV\config.toml`, `Documents\SatyrAV\projects\`, `Documents\SatyrAV\FONTS\`, `Documents\SatyrAV\log\`.
- **Types** — all shared data types: `Colour`, `Command`, `CommandType`, `RenderModifiers`, `ParticleType`, `Scene`, `Akt`, `RevySchema`, `ProjectData`. *(1.6.1)* `TextRun` gains `bold` / `italic`; `RevySchema` gains font-variant paths and subtitle defaults; `Scene` gains font-variant override paths. *(1.6.2)* `RevySchema` gains `creatorName` and parsed `year`. *(1.6.3)* `Command` gains `unknownKeyword`; `Scene` gains `warnings`; `RevySchema` gains `functionKeyAudio` map. *(1.7)* `CommandType` gains `Countdown` / `ClearCountdown`; `Command` gains `countdownSeconds` and `countdownLabel`. *(1.8.2)* `CommandType` gains `Typewrite`; `Command` gains `typeMsPerChar`. *(1.8.3)* `RenderModifiers` gains `layer`, plus `PathPoint` / `PathRepeat` / `pathPoints` / `pathDurationSec` / `pathRepeat` for `pathMove`. *(1.8.4)* New `CueNote` struct; `Scene` gains `cueNotes`, `Command` gains `cueName`, and free functions `RowCueName(cmd)` / `FindCueNote(scene, name)` resolve what a navigator row displays. *(2.0.0)* `Scene` and `RevySchema` gain `audioFade`. *(2.0.1)* `ParseColour(text, out)` is the one colour reader (13 names, `#RRGGBB`, `#RGB`). `Scene` gains `textColour` and `sourceLines`, and its `backgroundColor` defaults to "not set" (alpha 0); `RevySchema` gains `textColour`. Both replace the never-used `fontColour` fields.

### Render (`src/render/`)

- **Renderer** — manages the SDL windows and renderers: the master (operator) window, the slave (audience) window, and the optional capture-mirror window. `InitMaster` creates the control window. `InitSlave` creates the fullscreen projector window on the configured display, or a resizable window in windowed-dev mode. *(1.6.0)* `GetCanvasWidth/Height` returns the rect-authoring-space dims (the intended slave size in windowed-dev mode, slave bounds in fullscreen) — used by everything that interprets `TargetedDisplay` coordinates so windowed and fullscreen behave identically. All slave content is drawn into an offscreen target that `CompositeTargetedDisplay` then places inside the targeted-display rect; *(2.0.0)* that target is always canvas-sized, so the capture mirror, which copies it, keeps full resolution whatever the rect. *(2.0.0, SDL3)* Displays are still chosen by 0-based index in every config file and in the UI; `DisplayCount()` / `DisplayIdForIndex()` are the single bridge to SDL3's display IDs. Fullscreen windows are created in one step with position, borderless and fullscreen set together, followed by `SDL_SyncWindow`. `CreatePreferredRenderer` asks for the `direct3d11` driver and falls back to SDL's choice, and sets `SDL_HINT_RENDER_DIRECT3D_THREADSAFE` so the video decoder can share the device.
- **TextRenderer** — TTF text rendering with separate font sizes for master and slave. Handles text outline rendering via `TTF_SetFontOutline`. *(1.6.1)* Holds a 4-slot face table per side (regular / italic / bold / bold-italic) keyed by `(bold ? 2 : 0) | (italic ? 1 : 0)`. `Init` takes the three optional style paths; `SetSlaveFontPaths(...)` swaps the slave-side path set on scene change with empty-means-keep-existing semantics. `PickSlaveFont(bold, italic)` walks bold-italic → bold → italic → regular for graceful degradation. `DrawTextSlave` / `DrawTextSlaveRotated` / `DrawTextCenteredSlave` / `MeasureSlave` accept optional `(bool bold, bool italic)` so the multi-run line layout in `SlaveWindow` picks the matching face per segment.
- **MasterWindow** — draws the header, revy title, and the navigator with line numbers, scrolling, and truncation. *(1.6.0)* Long commands wrap to continuation rows via real pixel-width measurement (`MeasureWidth`) with binary-search fitting and word-aware breaks; the primed-row highlight spans every wrapped row. *(1.8.4)* A fourth, read-only **Cue Notes** column draws each row's `[Cue]` note to the right of its command. The note shares the command's row block — whichever wraps taller sets the height — so notes stay level with their commands and the 1.6.4 wrap-aware scroll clamp still measures the last screenful correctly. The column claims width only when the selected scene defines notes, leaving projects that don't use the feature with the command column they had.
- **SlaveWindow** — manages the projector output: background colour, text entries (centered or positioned), a list of active images with render modifiers, and a list of active particle systems. Each text/image/particle entry carries an optional group tag. *(1.5 / 1.6.5)* Ungrouped and grouped entries both **append** — successive `show` / `particle()` calls coexist rather than replacing each other; `clear` / `clearImages` drop them together. Layers draw in order: background → video → images → particles → text. *(1.6.1)* `SlaveTextEntry::subtitleAnchor` flag and `PushSubtitleRuns(...)` add a bottom-anchored centred-X layout for `textD` subtitles; a pre-pass in `DrawText` assigns per-subtitle `subtitleBottomY` so multiple subtitles stack upward instead of overlapping. *(1.7)* A `SlaveCountdownEntry` list holds live timers; the `DrawText` tail formats each as a zero-padded `MM:SS` string from elapsed wall-clock time and draws it centred near the top of the canvas (stacking downward for multiple timers). `ClearCountdowns()` and `ClearAll()` remove them; `clearText` deliberately does not, and `PerformanceScreen` drops them on scene change so a countdown is scene-scoped. *(1.8.2)* `SlaveTextEntry` gains typewriter state (`typeMsPerChar` / `typeCharOffset` / `typeComplete`); `DrawText`'s wrap pre-pass resolves each entry to its currently-visible runs, revealing by UTF-8 character so a Greek letter is never cut mid-codepoint, and `CompleteTypewriters()` snaps a half-typed line when the operator advances the cue. *(1.8.3)* `InsertImageByLayer` keeps `imageEntries` sorted by `layer()` at push time (ties in push order, so an all-default scene is byte-identical to pre-1.8.3), and the duplicated two-point `move()` lerp in the text and image paths was replaced by one `EvalAnimatedPosition` helper that serves both `move()` and `pathMove()`. *(2.0.1)* `SetDefaultTextColour` sets the colour for text with no `colour(...)` of its own. It is captured into each `SlaveTextEntry` and `SlaveCountdownEntry` when pushed, so text left on screen keeps its colour into the next scene.
- **MediaPlayer** — threaded video and audio playback using FFmpeg. Owns a map of per-path `VideoPlayback` decode contexts so the videos of the previous, current and next scene can be **preloaded**, moving decode work off the playback critical path. Each `VideoPlayback` owns its FFmpeg state, decode thread, frame ring, audio stream and display texture. *(2.0.0)* A frame reaches the screen by one of three paths, chosen per clip: **zero-copy** (Windows, hardware decode on the slave renderer's own D3D11 device; the ring holds references to decoder surfaces and the frame never leaves the GPU), **hardware read-back** (decoded on the GPU, read back to system RAM and converted), or **software**. The last two are the pre-2.0.0 paths and are the automatic fall-backs. *(2.0.0)* Sound: one logical SDL audio device stays open, and every source — each video and each standalone sound — owns an `SDL_AudioStream` bound to it, so sounds play over each other and over video sound. The playback clock is driven by how much audio the device has consumed. `SeekVideo` / `GetVideoPosition` / `GetVideoDuration` are seek plumbing with no commands attached yet. *(1.6.0)* `HasVideo()` is true while a video is loaded, including paused, so `K`-pause holds the last frame on screen. A preload budget (4 GB by default) is split in command-priority order across the clips in the scene window. See [video-pipeline.md](video-pipeline.md) for full details. *(2.0.1)* Pausing one source unbinds its stream rather than pausing the device, so `K` and `M` no longer silence each other's sounds. With no audio device, or one that stops consuming mid-clip, a video drops its sound and runs on the wall clock instead of freezing; see [video-pipeline.md](video-pipeline.md#clock).
- **D3D11Interop** *(2.0.0)* — the only code that includes `<d3d11.h>`, so the Windows headers stay out of `MediaPlayer`. `CreateSharedDeviceCtx` builds FFmpeg's hardware-decode context on the slave renderer's D3D11 device after switching the device to multithread-protected mode. `CopyFrameToTexture` is the zero-copy step: a GPU-to-GPU copy from a decoder surface into an NV12 SDL texture. On other platforms both are stubs that report "unavailable", which selects the software path.
- **RectF** *(2.0.0)* — one helper, `FRectI(x, y, w, h)`, converting integer layout rectangles to the float rectangles SDL3's render calls take.
- **MediaCache** — pre-loads image textures and tracks all preloaded file sizes. Supports 3-scene preloading (previous, current, next) with eviction of out-of-scope assets. Animated `.gif` files are decoded frame-by-frame via `IMG_LoadAnimation` and exposed to the slave as a texture array plus per-frame delays.
- **ParticleSystem** — CPU particle emitter. 10 motion models: `RAIN`, `SNOW`, `CONFETTI`, `RISE`, `SCATTER`, and *(1.4)* `BROWNIAN`, `OSCILLATION`, `ORBIT`, `NOISE`, `LIFECURVE`. Supports trails *(Ghost / Stretch / Glow, 1.4.1)*, edge-bounce reflection, per-type speed/density/X-distribution tunables sampled per spawn, and a sticky smooth-stop mode that lets live particles finish after `stopParticleCont`.

### Input (`src/input/`)

- **InputHandler** — translates raw SDL keyboard events into `InputAction` enum values. Handles modifier keys (SHIFT for step-back and jump navigation, CTRL for top/bottom jumps). *(1.6.3)* Emits `InputAction::FunctionKey` for `SDLK_F1..F12` with the F-number on a `lastFunctionKey` side channel; suppressed in text-input mode so typing in a search field can't fire a hotkey. *(2.0.0)* SDL3 scopes text input to a window; the master window is registered once with `SetTextInputWindow`, so screens still call `SetTextInputMode(bool)`. *(2.0.1)* `O` maps to `InputAction::MarkLine`. `App` still takes `O` first while the Debug popup is open, for the `D → O` Overview chord.

### UI (`src/ui/`)

- **Widget** — base class with position, size, focus state.
- **ListView** — scrollable text list with selection highlight.
- **TextField** — single-line text input with cursor.
- **Dropdown** — expandable option selector.
- **Popup** — base class for draggable, opaque popup windows with title bar.
- **HelpPopup** — shows all keyboard controls, contact email, version. Context-aware (shows different controls when in a project vs. in menus).
- **DebugPopup** — two-column display of runtime info: scene context, last command with path/exists check, slave display resolution, font cascade values, cache stats, video buffer level, *(2.0.0)* the decode path of the playing video (`Hardware (zero-copy)`, `Hardware (read-back)`, `Software`, or `no video`) and the number of standalone sounds playing. *(1.6.0+)* Footer hint advertises the `S` (Display rect) and `O` (Overview Debug) sub-popup chords.
- **DisplaySizePopup** — modal `D → S` editor for the targeted-display rect (move / scale / rotate with `WASD`/`Z`/`X`/`Q`/`E`, `SHIFT` for fine precision, `C` to reset).
- **OverviewPopup** *(1.6.3)* — modal `D → O` scene-health report. Walks every scene of the active project on `Open()` and renders parser warnings (unknown keywords) and missing media files referenced by `show` / `play`. Cached at open time so projects with many scenes don't re-scan per frame; UP/DOWN scrolls, ESC closes.

## Data flow

1. User presses ENTER on a command in `PerformanceScreen`
2. `ExecuteCommand()` calls `CueEngine::ExecuteCurrentCommand()`
3. CueEngine looks up the `Command` struct and calls the slave callback
4. `OnSlaveCommand()` dispatches by `CommandType` — text goes to `SlaveWindow`, media goes to `MediaPlayer`, images go through `MediaCache`
5. On the next frame, `SlaveWindow::Update()` clears the slave, draws video/images/particles, then `DrawText()` renders text on top
6. `PerformanceScreen` presents the slave window; `App::Run()` presents the master window (with popups overlaid) and, when enabled, the capture mirror

## Threading model

The main thread handles all SDL rendering, input, and UI. Each loaded video has its own background thread running the FFmpeg decode loop, so with preloading there are usually several, of which only the playing clip's is busy. SDL mixes and plays audio on its own internal thread, pulling from every bound audio stream. Threads communicate through SDL mutexes and condition variables and, for audio, through the streams themselves. *(2.0.0)* On Windows the decode threads and the main thread share the slave renderer's D3D11 device, which is put into multithread-protected mode for that reason.
